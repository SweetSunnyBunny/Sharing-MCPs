# Sharing snapshot review

Snapshot date: 2026-09-27.

This review covers all 30 package folders, collection documentation, and public
refresh/verification helpers. The UI and each cloud setup are separate siblings.
Generic configuration examples are included; populated environment files are not.

This is a review of the included packages, not a claim that every system on the
original PC is distributed. The broader inventory in
[shared-docs/COVERAGE.md](shared-docs/COVERAGE.md) identifies optional custom code
still outside this snapshot.

## Source coverage and intentional adaptations

The UI was refreshed from the maintained Anam application, and the 12 supporting
cloud/setup folders from their maintained service sources. `ui/EXPORT-MANIFEST.json`
records the selected source and reviewed generic overlays. Runtime code and browser
assets include provider, chat, voice, World Feed, memory and wearable integration.

Cloud Qualia is `mind-backend`: all 19 migrations and its current Worker/retrieval
modules are included. `qualia-mcp` is now a small stdio adapter to that current
service; its obsolete personal local implementation is not distributed. Limbic
includes its engine, both schema migrations, recipes and fictional starter data.
The remaining pre-existing MCP packages were reviewed for personal defaults,
local dependencies and installation instructions; they are not represented as
byte-for-byte copies of Anam or as newly upgraded third-party projects.

Privacy adaptations intentionally differ from the private installation: generic
configuration, fictional identities and prompts, empty runtime state, user-configured
services, and neutral narrative renderers replace the original installation's data.
Removing a name alone does not remove personal information: private biographies,
quoted conversations, medical/household episodes, device defaults and schedule
data were also reviewed and removed or replaced with generic configuration.

## Dependency gaps repaired

- The UI now includes its browser-profile launcher and gateway test fixture.
  Machine-tool wrappers, OAuth helpers and attachment analysis resolve the
  included sibling packages; path overrides remain available.
- The private process-supervisor layout is no longer required. Watchdog services,
  optional archives, content directories and home effects are configured by each
  installer. See `ui/EXTERNAL_INPUTS.md`.
- The local Memory Core package uses package-local data/import paths. Its obsolete
  Qualia hook is retired; optional companion plugins require explicit configuration.
- Missing declared dependencies and Discord Scribe setup instructions were added.
  Old hardcoded workstation, archive and authentication-file paths were removed.
- Qualia, Limbic and Hearth have fictional starter SQL and empty-database setup
  guidance. The same configured identity IDs work across services. Hearth accepts
  identities registered in its database; Limbic accepts the UI's interaction aliases.
- `shared-docs/CONNECTIONS.md` maps deployment order and required external services.
  `ui/mcp-servers.example.json` is an inactive, placeholder-only connection example.

Provider accounts, Cloudflare resources, OAuth consent, installed apps, models
and user-selected files are external requirements. Some optional systems also
need custom implementations not included here, notably the full Commons world
server. The coverage map separates those source-code gaps from private data.

## Privacy review

The review covered names, account/voice IDs, deployment hosts, local paths,
credentials, private prose and identity-specific runtime defaults. It combined
exact-value comparisons against local private configuration, configured pattern
checks and independent semantic review. No known private matches or unresolved
personal-content findings remained in the final reviewed files.

A populated Discord Scribe env file, installed dependencies and its old nested ZIP
were moved into private storage outside this collection. A leftover local agent
settings directory and generated bytecode caches were also removed from the shared tree. Generic `.env.example`
and `.dev.vars.example` files remain as setup templates. Private prompts, personal
media, histories, tokens, databases, logs, backup files and compiled applications
are excluded. The generic app icon was visually reviewed.

These are checks of this snapshot, not a guarantee for future edits. Exported
source changes need another review, especially comments, docstrings and defaults
that could describe a real person even after names have been replaced.

## Newcomer installation pass

All 30 package entry READMEs now explain prerequisites, the exact working folder,
commands, configuration values, a first successful check and troubleshooting.
The collection starts at `START_HERE.md`; optional components and external
requirements are identified before installation. Nested component guides were
updated too, including Android and the machine-agent scaffold.

The UI has a separate ChatGPT browser-bridge guide. Its profile/port defaults
now agree, custom ports are passed to the launcher, and Test Connection performs
a read-only browser check. It explicitly does not certify login or a completed
reply. Empty or example cloud-health URLs no longer delay first startup.

The UI dependency declarations now include the libraries actually imported by
the offered providers and Windows CLI runtime. The lockfile retained existing
versions and added OpenAI SDK and Windows PTY dependencies. Install instructions
use the matching lockfile rather than a floating dependency installation.

The install walkthrough also repaired Google OAuth scopes affected by over-broad
redaction, supplied the missing machine scaffold template, updated YouTube's
transcript API compatibility and added X's local stdio entry point. Additional
private narrative comments found during the source walkthrough were removed.

Checks for these changes: 53 targeted UI tests, all 29 JavaScript files parsed,
lock consistency and an isolated locked-install dry run; two offline YouTube
regressions; X stdio launcher verification; Google helper syntax and redaction
regression; local machine-scaffold generation. Documentation JSON examples,
PowerShell syntax, entry paths and relative links were checked. No cloud resource,
OAuth login, provider generation or account action was performed.

A full fresh-machine installation of the heavy model/audio dependencies and
live end-to-end tests with an installer's accounts remain recommended release
checks. The guides state those account-dependent success steps explicitly.

## Broader system coverage audit

A subsequent read-only inventory compared the collection with local service
sources, cloud source trees, MCP configuration discovery and supporting projects.
All 54 inspected implementation modules in the maintained cloud `src` trees have
corresponding public files. That establishes source-file coverage, not live
deployment health or byte-for-byte identity after privacy adaptations.

The larger installation has additional custom MCP adapters, a Commons world
engine and newer OAuth connector, two separate Android clients, and hosting and
supervisor code outside this collection. Configured upstream tools and desktop
plugins are also separate installations. The new coverage map records those
boundaries; missing reusable implementations are no longer described as merely
private content or account requirements.

The included audio package was also found to lag behind its maintained service
wrapper. It now exposes all nine maintained tools, with video URL support,
explicit optional browser-profile configuration, standalone optional Groq
transcription and a loopback HTTP mode. The six existing tools remain available.
Failed or unavailable transcripts can retry after configuration is corrected.
The analysis engine still matches the maintained source byte-for-byte.

Twenty offline audio tests passed, covering registration, compatibility,
URL/profile handling, transcription retries and transport selection. Media
processes and remote transcription were mocked; no real browser profile, video
download, provider call or full dependency installation was exercised.

## Distribution and rechecking

`SETUP_MANIFEST.json` covers every reviewed package file and helper in this
collection. Run `python scripts/verify_setups.py` to check hashes and reject
unreviewed additions or runtime/private artifacts. Generic examples are accepted.

Existing repository Git history retains older versions and is outside this review.
Use `python scripts/build_clean_archive.py --output PATH` to create a distribution
from the reviewed manifest only. That archive includes no Git history or runtime
state. Changing files requires review and a refreshed manifest before packaging.
